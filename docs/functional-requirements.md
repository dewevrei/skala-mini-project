# Functional Requirements

문서 상태: 구현 계약 확정본  
기준일: 2026-08-18  
서비스: AI 칸반보드 & 개인 과제 관리자 MVP

## 목적과 범위

여러 Google 사용자가 로그인할 수 있지만 각 사용자의 데이터는 완전히 분리되는 개인용 작업 관리 서비스다. 사용자는 프로젝트별 칸반보드에서 일반 작업을 직접 등록하거나, 제목과 설명을 Gemini에 전달해 실행 가능한 평면 작업 목록을 생성한다. 협업, 공유, 마감일, 예상 시간, 자동 일정 편성은 MVP 범위에서 제외한다.

## 요구사항

| 요구사항 ID | 요구사항명 | 상세 요구사항 내용 | 중요도 | 난이도 | 비고/제약사항 |
|---|---|---|---|---|---|
| REQ-FUNC-001 | Google OAuth 로그인 | 모든 Google 계정은 Google OAuth 2.0으로 로그인할 수 있어야 한다. 일반 회원가입과 비밀번호 로그인은 제공하지 않는다. | 필수 | 높음 | Spring Security 세션 인증 사용 |
| REQ-FUNC-002 | 사용자 자동 등록·동기화 | 최초 로그인 시 사용자를 생성하고 이후 로그인마다 Google의 `name`, `email`을 갱신한다. `google_id`로 계정을 식별하며 사용자가 정한 `nickname`은 덮어쓰지 않는다. | 필수 | 중간 | `google_id`, `email`은 유일 |
| REQ-FUNC-003 | 최초 닉네임 생성 | 최초 로그인 시 `trim(Google 이름) + "-" + 소문자 전체 UUID` 형식의 충돌 없는 닉네임을 자동 생성한다. | 높음 | 낮음 | 전체 길이가 255자를 넘지 않도록 이름 부분만 줄임 |
| REQ-FUNC-004 | 닉네임 변경 | 회원정보 변경 화면에서 닉네임을 변경할 수 있어야 하며 대소문자를 구분하지 않고 중복을 금지한다. | 높음 | 중간 | 회원 탈퇴는 범위 밖 |
| REQ-FUNC-005 | 로그아웃 | 로그인 사용자는 현재 세션에서 로그아웃할 수 있어야 한다. 로그아웃 성공 후 Frontend `/login`으로 이동한다. | 필수 | 낮음 | Redis 세션 삭제 및 쿠키 즉시 만료 |
| REQ-FUNC-006 | 사용자 데이터 격리 | 사용자는 자신이 소유한 프로젝트, 열, 작업만 조회·변경·삭제할 수 있어야 한다. | 필수 | 높음 | 공유·초대·협업 없음 |
| REQ-FUNC-007 | 프로젝트 생성 | 이름(필수)과 설명(선택)으로 프로젝트를 생성할 수 있어야 한다. | 필수 | 중간 | 같은 사용자 내 이름 중복 금지, 대소문자 무시 |
| REQ-FUNC-008 | 기본 보드 열 생성 | 프로젝트 생성과 같은 트랜잭션에서 `Todo`, `In Progress`, `Done` 열을 이 순서로 생성해야 한다. | 필수 | 중간 | 하나라도 실패하면 프로젝트 생성 전체 취소 |
| REQ-FUNC-009 | 프로젝트 조회 | 사용자는 자신의 프로젝트 목록과 프로젝트 상세를 조회할 수 있어야 한다. 목록은 `createdAt DESC, id DESC`의 최근 생성순으로 표시한다. | 필수 | 낮음 | 다른 사용자 자원은 노출하지 않음 |
| REQ-FUNC-010 | 프로젝트 수정 | 프로젝트 이름과 설명을 수정할 수 있어야 한다. | 높음 | 낮음 | 이름 유일성 유지 |
| REQ-FUNC-011 | 프로젝트 삭제 | 경고 모달에서 명시적으로 확인하면 프로젝트와 포함된 모든 열·작업을 완전 삭제해야 한다. | 필수 | 높음 | 복구 기능 없음 |
| REQ-FUNC-012 | 보드 열 추가 | 프로젝트에 사용자 정의 열을 추가할 수 있어야 하며 새 열은 현재 마지막 열 뒤에 추가한다. | 필수 | 중간 | 새 열 이름은 프로젝트 내 유일; 이후 순서 변경 가능 |
| REQ-FUNC-013 | 보드 열 수정 | 기본 열을 포함한 모든 열의 이름을 변경할 수 있어야 한다. | 높음 | 중간 | 대소문자 무시 중복 금지 |
| REQ-FUNC-014 | 보드 열 정렬 | 모든 열의 순서를 드래그 앤 드롭으로 변경하고 저장할 수 있어야 한다. | 필수 | 높음 | 현재 첫 번째 열이 AI 등록 대상 |
| REQ-FUNC-015 | 보드 열 삭제 | 경고 모달 확인 후 열과 그 열의 모든 작업을 완전 삭제해야 한다. | 필수 | 높음 | 마지막 남은 열은 삭제 불가 |
| REQ-FUNC-016 | AI 기본 열 결정 | 현재 보드에서 첫 번째 열을 AI 생성 작업과 AI 실패 대체 작업의 등록 열로 사용해야 한다. 열 순서 변경 시 기본 열도 즉시 변경된다. | 필수 | 중간 | 별도 기본 열 플래그 없음 |
| REQ-FUNC-017 | 보드 일반 작업 등록 | 보드의 특정 열 `+`에서 일반 작업을 등록하면 선택한 열의 맨 아래에 생성해야 한다. | 필수 | 중간 | 제목 필수, 설명 선택, 우선순위 1 |
| REQ-FUNC-018 | Items 일반 작업 등록 | Items 화면의 특정 열 그룹 `Add item`에서 일반 작업을 등록하면 해당 열의 맨 아래에 생성해야 한다. | 필수 | 중간 | 전역 일반 등록 없음 |
| REQ-FUNC-019 | 일반 작업 입력 | 일반 작업은 `title`과 선택적 `description`을 받으며 저장 우선순위는 항상 `1`이다. | 필수 | 낮음 | 사용자가 우선순위를 선택하지 않음 |
| REQ-FUNC-020 | AI 작업 생성 요청 | `AI Generate`는 필수 `title`, 필수 `description`을 Spring AI `ChatClient`를 통해 Gemini에 전달해야 한다. | 필수 | 높음 | 프로젝트의 현재 첫 번째 열 대상 |
| REQ-FUNC-021 | AI 평면 작업 분해 | Gemini는 원본을 상·하위 계층으로 저장하지 않고 독립 작업 목록으로 분해해야 한다. 작업 수의 비즈니스상 최소·최대 제한은 두지 않는다. | 필수 | 높음 | 각 항목은 `title`, `description`, `priority` |
| REQ-FUNC-022 | AI 작업 설명 조합 | 백엔드는 저장 전에 각 AI 설명 앞에 사용자의 원래 제목과 고정 구분자 ` - `를 붙여야 한다. 원래 설명은 AI 문맥으로만 사용한다. | 필수 | 중간 | 정확한 형식: `원본 제목 - AI 설명` |
| REQ-FUNC-023 | AI 작업 저장 | 검증된 AI 작업들을 응답 배열 순서대로 현재 첫 번째 열의 맨 아래에 이어서 저장해야 한다. 원래 입력 작업은 별도로 저장하지 않는다. | 필수 | 높음 | 모든 항목을 한 트랜잭션으로 저장 |
| REQ-FUNC-024 | AI 우선순위 | AI 작업의 우선순위는 정수 `1~5`이며 `1`이 가장 높다. 저장 후 우선순위는 변경할 수 없다. | 필수 | 중간 | 자동 정렬 기준으로 사용하지 않음 |
| REQ-FUNC-025 | AI 응답 재시도 | AI 응답 구조 검증에 실패하면 동일 입력으로 한 번 재요청해야 한다. 재요청도 실패하면 대체 저장 규칙을 적용한다. | 높음 | 중간 | 부분 성공은 전체 실패 |
| REQ-FUNC-026 | AI 실패 대체 저장 | AI 호출 실패 또는 최종 응답 검증 실패 시 원래 `title`, `description`으로 일반 작업 1건을 현재 첫 번째 열에 우선순위 `1`로 저장해야 한다. | 필수 | 높음 | 사용자에게 AI 실패 사실을 별도 표시하지 않음 |
| REQ-FUNC-027 | AI 저장 원자성 | 정상 AI 결과의 DB 저장 중 오류가 발생하면 전체를 롤백하고 `500` 오류를 반환해야 한다. 이 경우 일반 작업으로 대체 저장하지 않는다. | 필수 | 높음 | 부분 저장 금지 |
| REQ-FUNC-028 | Items 그룹 조회 | Items 화면은 현재 보드 열 순서대로 그룹을 표시하고, 각 그룹 안에서는 저장된 카드 순서를 사용해야 한다. | 필수 | 중간 | 평면 전체 목록 방식은 폐기 |
| REQ-FUNC-029 | 보드 조회 | 보드는 열 순서와 각 열의 카드 순서를 그대로 표시해야 한다. 우선순위로 자동 정렬하지 않는다. | 필수 | 중간 | 새 작업은 맨 아래 |
| REQ-FUNC-030 | 카드 수동 정렬 | 같은 열 안에서 카드를 드래그하면 사용자가 놓은 순서를 저장하고 유지해야 한다. | 필수 | 높음 | 마지막 저장 결과가 최종 상태 |
| REQ-FUNC-031 | 카드 열 이동 | 보드에서 카드를 다른 열의 특정 위치로 드래그하면 열과 위치를 함께 변경해야 한다. | 필수 | 높음 | 대상 프로젝트 밖 이동 금지 |
| REQ-FUNC-032 | Items 상태 이동 | Items 화면의 `Status` 선택으로 다른 열을 지정하면 대상 열 맨 아래로 이동해야 한다. | 필수 | 중간 | 상태 값은 열 이름으로 표시 |
| REQ-FUNC-033 | 제목 검색 | Items 화면에서 현재 프로젝트의 작업을 `title` 포함 검색할 수 있어야 한다. | 높음 | 중간 | 대소문자 무시; 빈 검색어는 전체 표시; 그룹 구조 유지 |
| REQ-FUNC-034 | 작업 수정 | 작업의 제목과 설명을 수정할 수 있어야 한다. | 필수 | 중간 | 우선순위는 수정 불가 |
| REQ-FUNC-035 | 작업 삭제 | 경고 모달 확인 후 작업을 완전 삭제해야 한다. | 필수 | 중간 | 복구 기능 없음 |
| REQ-FUNC-036 | 요청 중 중복 클릭 방지 | 일반 등록 및 AI 등록 요청 중 해당 버튼을 비활성화하고 완료 후 다시 활성화해야 한다. | 높음 | 낮음 | 서버 멱등성 키는 제공하지 않음 |
| REQ-FUNC-037 | 화면 상태 갱신 | 현재 탭은 변경 요청의 서버 응답으로 즉시 갱신하고, 다른 탭은 다시 활성화될 때 최신 프로젝트 상태를 조회해야 한다. | 높음 | 중간 | 실시간 연결·주기 조회 없음 |
| REQ-FUNC-038 | 공통 API 응답 | JSON REST API의 성공·실패 응답은 `success`, `code`, `message`, `data` 필드를 갖는 `ApiResponse<T>`를 사용해야 한다. | 필수 | 중간 | OAuth 리다이렉트 응답은 예외 |
| REQ-FUNC-039 | 인증 화면 이동 | Google 로그인 성공 시 `/projects`, OAuth 실패 시 `/login?error=oauth`, 로그아웃 성공 시 `/login`으로 이동해야 한다. | 높음 | 낮음 | Redis 장애 callback은 `/login?error=session-service-unavailable` |
| REQ-FUNC-040 | Task 등록 취소 | Board 또는 Items의 공통 Task 등록 modal/overlay에서 `Cancel`을 누르면 일반 Create·AI Generate 모두 입력 변경 여부와 관계없이 확인창 없이 입력을 폐기하고 등록을 시작한 화면을 그대로 보여줘야 한다. | 높음 | 낮음 | 별도 등록 route 없음 |

## 명시적 범위 제외

- 사용자 간 프로젝트 공유, 초대, 공동 편집
- 상위 작업과 하위 작업의 계층 구조
- 시작일, 마감일, 예상 소요 시간, 캘린더 및 자동 일정 편성
- 담당자, 카테고리, 저장소, 첨부 파일, 로드맵
- Markdown·리치 텍스트 편집
- 회원 탈퇴
- 서버 측 요청 멱등성
- 운영 배포 구성
